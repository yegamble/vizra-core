# HOW TO READ line (a), exactly
############################################################################

Line (a) is `make ci` on the mutated tree. It does NOT say the same thing for
every mutation, and the difference is the whole point:

  M1  SHELL := /usr/bin/true            make ci exit=0
  M2  MAKEFLAGS += -i                   make ci exit=0
  M3  included MAKEFLAGS += -i          make ci exit=0

      These three neuter the SHELL or make's error handling, so every recipe in
      the file is disarmed at once — INCLUDING the `ci-guard` recipe's own
      invocation of this guard. `make ci` reports success with a failing test
      suite underneath it. That is the defect, reproduced. The only readings
      that go red are the out-of-make anchor (b) and the direct `go test` (c).

  M4  a '-' prefix on test-race          make ci exit=2
  M5  '|| true' on test-race             make ci exit=2
  M6  a duplicate 'ci:' target           make ci exit=2

      These disarm one recipe line or one target and leave the shell intact, so
      the in-recipe guard still runs and `make ci` goes red AT ci-guard — not
      because it noticed the failing test. Measured directly on this clone:

          ==> ci-guard
            FAIL  Makefile:159 — gate target `test-race` has a recipe line
                  prefixed `-`: `@-$(GO) test -race -count=1 $(PKGS)`
          make-integrity-guard: FAILED
          make: *** [ci-guard] Error 1

      So for M4-M6 `make ci` is red for the right reason, but through the
      in-recipe invocation — which a seventh mutation (deleting that one line
      from the `ci-guard` recipe) would remove. The out-of-make anchor (b) does
      not depend on it, which is why the anchor is the control and the
      in-recipe invocation is documented in the Makefile as local parity only.

WHAT LINE (a) DOES NOT SHOW, said plainly: at the BASE commit, before this PR,
M4/M5/M6 would have left `make ci` exiting 0 with the test failure swallowed
(there was no guard to catch them). That counterfactual was not re-measured
here; what was measured is that at THIS commit all three are red by name at
three independent readings.
