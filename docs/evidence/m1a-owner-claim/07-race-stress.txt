# TestOwnerClaimRaceYieldsExactlyOneOwnerUnderEveryServerDefaultIsolation — stress runs (closing slice)

Each run executes the test binary with -test.count=N -test.v and counts the
`--- PASS/FAIL` line of every isolation sub-test. One iteration = 32 concurrent
claimants under EACH of the three server default isolations (read committed,
repeatable read, serializable), on a fresh database schema per sub-test.

Binaries: `integ-655f46a-norace.test` = `go test -tags=integration -c` of
`git archive 655f46a` (the head CI failed on); `integ-a42ca76.test` /
`integ-a42ca76-race.test` = the same without / with -race at a42ca76 (the fix).
`git diff a42ca76 c79c4d2 -- internal cmd migrations api store go.mod go.sum` is
empty, so these binaries test the same product and test code as the pushed head.

The non-race binary is used for the 200x runs for throughput (5-14 s per
iteration versus 26-75 s under -race on this host, as measured below); two -race runs of 20 follow.
Services: PostgreSQL 18.6, Valkey 9.1.2, Redis 7.2.16 (the CI digests), one
database per concurrent run. Host: darwin/arm64, 8 CPUs, shared with other work
(load averages are recorded per run; "contended" adds 16 busy loops on top).
"contention" labels in the first runs were printed by an earlier version of the
script as "0/1 (16 busy-loop processes ...)"; they are normalised below and the
counts are untouched.
